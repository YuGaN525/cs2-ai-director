## 1.16.2 Windows 并发凭据锁修复

在导播与三个训练器正常运行时，补充执行实际冻结 EXE 的 `--account-check`，启动异常窗口报告 `PermissionError: [Errno 13] Permission denied`，堆栈定位到 `DeviceSession._transaction` 在获取字节锁之前执行的 `lock.read(1)`。Windows 强制字节锁也禁止另一进程读取该字节，因而初始化检查绕过了原本的等待机制。已打开导播的自动模型接收和上述序号 5 证据仍有效；该次额外诊断未成功，不能记作通过。

修复用 `os.fstat` 检查锁文件长度，避免读取已锁定字节；随后仍使用原 `LK_LOCK` 获取互斥锁。账号验证、DPAPI、签名、离线时限和注销边界不变。新增真实 Windows 跨进程测试：另一进程持有锁时必须等待，释放后获取且可复用；旧代码明确复现 PermissionError，修复后通过。账号、签名模型、离线许可及拆分的 73 项针对检查通过，其中 1 项既有环境条件跳过。

## 根据实测准备的逐点优化步骤

以下是后续实现要求，不代表本轮已经开发：

1. **统一主流程。** 首页按“选择原录像 → 检查容量和来源 → 解析与训练 → 自动上传 → 管理员纳入 → 云训练 → 正式模型到达”展示当前阶段。桌面仅保留本地任务与上传状态；网站工作台负责审核、BO 核实、云任务和模型发布，避免同一操作多处入口。
2. **目录预检与完整来源分批。** 选择目录后显示原件数、总字节、可重用解析结果及容量估算；正式执行仍核验原件摘要。按完整来源规划小于固定 180,000 行的提交批次，保留全部输入。估算不足时安全重规划，不能截断候选组或自动丢弃超限来源；BO 未核实应明确待审。
3. **解析错误可定位、可恢复。** 显示失败文件、稳定错误码和受影响阶段，已成功结果可保留以减少重做；恢复时必须重新校验源文件和解析版本。未知队伍等数据质量计数单列，不能静默填值或跳过后报告全部成功。
4. **训练进度与评估范围。** 显示解析 x/y、训练 trial x/y、运行耗时及本地输出目录。录制级评估明确标注“非 BO 隔离泛化验收”；正式模型的 BO 训练/验证/测试分组和质量门由云端报告独立展示。不能把本地候选训练成功当作服务器发布。
5. **自动上传与持久回执。** 主流程直接显示待上传、正在传输、服务器校验、已接收待审等状态；保留断点续传、身份隔离、摘要校验和重复提交保护。失败信息提供可执行的恢复动作；日常界面折叠 runId、摘要等技术信息，详情中可复制。
6. **审核状态和旧数据保留。** 网站在工作台合并相同用途入口，将工作台放在 AI 导播功能栏首位；删除公测批次操作入口时保留已有授权与历史记录。展示本轮接收量、待审/纳入来源、云训练选中量及历史库总量，接收不等于纳入，纳入不等于已用于新模型。
7. **客户端模型到达反馈。** 客户端显示正式模型版本、签名校验结果和更新时间。运行时按既有安全切换机制生效；离线失败不破坏当前有效模型。网站显示发布范围和实际版本，避免把发布成功当成所有客户端已收到。
8. **视觉和交互验收。** 默认浅色，复核深色边缘、滚轮、焦点顺序、弹窗工作区约束及长路径。先复现冻结版设置无响应，再做有证据的修复；用实际冻结 EXE、当前 Windows DPI 和连续流程验证，源码自检不能替代这一步。
