# 运镜适配：MulNX 主链路与 HLAE 后续事项

2026-11-07 用户明确更正：本项目正常使用 MulNX_CS2；HLAE 纳入后续适配开发事项。

## 当前实现与兼容

- 当前运镜通过用户在 MulNX 中配置的快捷键触发，POV 仍使用观察者数字键。
- `hlae_spawn_ct_key`、`hlae_spawn_t_key`、`hlae_bomb_a_key`、`hlae_bomb_b_key` 及对应 mode 是早期命名；继续读写，旧配置与备份无需迁移。界面、帮助和运行日志改为 MulNX。
- 默认单键保持 30ms、修饰键提前 80ms、双击按下间隔 80ms、最后主键释放后修饰键继续保持 300ms。没有为了减少耗时删掉这些等待。
- 官方参考固定为 `7181f6a160bd39915ad586599ee84f19f102db82`。输入系统约每 10ms 轮询，默认连击阈值 200ms，消费连击时检查修饰键当前状态。因此现有 300ms 修饰键尾部保持有明确依据；真实机器的版本和运镜绑定仍需现场核对。
- 发送成功只说明按键适配器完成调用，不能代替游戏内镜头观察确认。保留 GSI/前台/人工接管/许可/停止门。
- 当前继续使用同步按键兼容路径。异步化可能改变按下时间与观察反馈时序，在真实 MulNX 对照验收之前不默认启用。

参考：[官方仓库](https://github.com/Co1Swet/MulNX_CS2)、[固定版本输入处理](https://github.com/Co1Swet/MulNX_CS2/blob/7181f6a160bd39915ad586599ee84f19f102db82/source/MulNX/Systems/InputSystem/InputSystem.cpp)、[阈值定义](https://github.com/Co1Swet/MulNX_CS2/blob/7181f6a160bd39915ad586599ee84f19f102db82/source/MulNX/Systems/InputSystem/InputSystem.hpp)。参考源码只用于核对行为，未复制其实现。

官方实时使用文档目前仍是施工提示；WebSocket 文档仅明确启动器入口 55203 和游戏内网关 55202，不能据此推定相机控制 API 已完成适配。当前没有新增网络相机调用。

## 更新后恢复与核对

用户确认：MulNX 随 CS2 版本更新需要重新下载，新下载的运镜包快捷键会重置为预设，可用原运镜包覆盖恢复。

1. 更新前备份当前已验证的整个地图运镜包，并记录程序四类快捷键、单/双击模式和文件 hash。
2. 按 MulNX 发布说明获取与 CS2 兼容的版本，保留新下载的原始副本，退出 MulNX 后恢复原运镜包到新目录 `CS2OBTool/CameraSystem/CamPacks`。
3. 设置中心“MulNX 更新与运镜包”选择实际安装目录和当前地图包。检查启动器、快捷键总开关、CT/T/ASIDE/BSIDE 宏的启用、修饰键、主键和连击次数。其他命名/结构显示未知，转人工核对，不猜测映射。
4. 核对只读取文件，不启动注入器、不覆盖外部文件；运行中的配置仍需停止后再应用。文件匹配不代表游戏当前加载该包，更不代表新版本真实镜头已通过。
5. 在观战环境依次确认 CT、T、A、B 镜头、人工接管、失焦与停止，记录 CS2/MulNX 版本、地图包 hash 和镜头反馈。未通过时保留旧包与测试记录用于回退。
