## 已实现

1. Demo 目录先枚举文件与原件总字节，再检查输出盘可用空间。原件两倍加 512 MiB 是准备预算，不是解析结果大小保证。解析完成后根据实际 CSV、各批快照及包预算再次检查本地队列上限和磁盘空间；不足时停止，保留原件。
2. `training_plan.py` 流式扫描完整来源，按 180000 行软目标、256 来源及保守字节预算规划。来源由真实 `match_source_id` 标识，不以文件名推断 BO。即使同来源行交错也归同批；超过软目标的单来源保持整体，超过 200000 行硬限额时明确报错，不截断或拆散候选组。元数据不完整拒绝猜测。
3. 所有批次先用现有 v1 exporter 校验候选组、字段、清单和各项硬限额，再进入训练。每批独立 `runId`、不可变输入及候选输出；GUI 普通训练、AI 辅助/本地搜索、供冻结程序使用的 CLI 入口源码均使用相同规划。Demo GUI 解析目录也独立，避免不同训练器覆盖共享 CSV。
4. 每批训练成功才进入原持久上传队列。某批失败即停止后续训练，已成功候选和队列保留；`completed.json` 记录已完成 run，提示可选择剩余 batch CSV 重试。上传失败从原队列恢复，不重新训练。汇总指标明确仅指最后一批，不冒充全部来源的统一模型。
5. 工作台显示检查、训练第 N/M 批、整理等真实阶段；独立上传汇总显示已接收/处理中/需处理数和实际上传字节。模型拟合仍使用不确定进度条，不编造百分比。服务器校验、回执接收、人工纳入、主动训练与模型发布明确分开。
6. 上传等待显示自动重试时间；手动继续不绕过既有退避。整理任务暂停后重试成功会恢复排队。已收到回执后释放内存进度记录，持久回执不变。
7. 旧 CSV 提示依据来源元数据，不再用 `ambiguous=0` 推断格式。旧 CSV 缺少上传所需字段时仍允许原本可行的本地训练，上传整理失败留在队列说明原因；不伪造来源或把旧数据当完整 Demo。无来源且超单包硬限额的输入需补齐来源/重解析。

规划和训练过程只操作本次选择的数据及新输出目录；工作线程处理文件、磁盘和网络，Tk 主线程仅展示结果。账号变化时停止后续批次，队列仍按原账号/设备隔离。
