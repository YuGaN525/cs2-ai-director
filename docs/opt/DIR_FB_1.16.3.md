## 现象、范围与修复

初查比较 1.16.0 `da254cb8` 与 1.16.2 `ad53cc8`，相关输入代码一致，正式包摘要与主模块/适配器字节码匹配。14 种情境分别作用于两版源码和两份包内代码，共 56 次观察，另有 2 次数字监听 AST 模拟。这些观察包含缺陷复现，不能称为安全回归通过。初查证据：`D:/Yuzibei/local-data/director-security-20261111/`。

1. `director_adapters/input.py` 取消前台成功缓存。每次 keydown、每段等待后重新检查 HWND、PID、完整进程路径，配置了 CS2 路径时必须一致。目标未知、失焦、实例改变、取消或授权失效时中止后续 down。
2. 数字切人、keyboard 组合键、pydirectinput 单键回退统一使用发送锁。所有等待拆成不超过 20ms 的片段；保留 MulNX 默认 80ms 前导、30ms 主键保持、80ms 连击间隔、300ms 尾部 Alt 保持。只释放本次实际持有的键，反向清理；发送失败不报告成功。
3. 自动聚焦仅保留首次启动便利。已经观察到游戏后用户切到其他窗口，不再反复抢回焦点；用户自行切回目标实例后恢复。
4. `physical_modifiers.py` 仅跟踪物理 Alt/Ctrl/Shift/Win 的左右键状态，丢弃注入事件与所有非修饰键，不保存键盘历史。监测未就绪即禁止自动输入；用户按修饰键则取消。若用户接管了程序正按住的同一左修饰键，不强制释放用户持键；不同侧键不会阻止清理程序自己的键。停止时卸载监测。
5. `ManualKeyWatcher` 在过滤数字、接管及日志记录前校验实时游戏焦点。非游戏数字不进入接管回调、日志或时间线。原全局暂停热键用途保持。

Windows 全局输入 API 不接受目标窗口参数，检查与系统分发之间仍有竞态；低级钩子还可能因操作系统超时被静默移除，异步键状态检查也不能完全区分同键物理/注入来源。该修复缩小并中止已发现的危险路径，不承诺操作系统层面的绝对隔离。日志中的“已发送”也不是实际镜头成功的证明。

## 日志上传

协议：`contracts/director-diagnostics-v1/README.md`，与网站逐字节同步。账号使用当前 DirectorDevice Bearer；产品资格到期不应妨碍求助，设备撤销、封禁等仍由服务端拒绝。

- 两个程序的设置中心增加手动脱敏预览、确认提交、待传记录及回执。标语统一为“一人解放整场比赛”。新窗口继续使用共享浅色/深色配色、可滚动预览与列表。
- 默认自动报告严重错误及异常退出，可关闭。关闭立即停止本进程自动采集，并停止自动排队和补传；手动确认仍可单次提交。手动报告离线失败后，在自动开关关闭时等待再次明确重试，不偷偷恢复自动传输。
- 白名单投影只保留程序事件类别、允许的异常类型、本程序文件名和代码行号。不会上传异常 message、任意原始文本、用户按键、路径、聊天、账号令牌、密钥、配置、转储或完整系统日志。历史数字接管行直接排除。仅读取明确命名的本程序日志，不遍历或打包目录。
- 本地队列最多 20 份/4MiB、30 天到期；自动同版本/故障指纹按归属 24 小时去重。SQLite 事务保证同一请求 ID/正文持久重试；进程中断发送后仍使用原 ID。
- 捕获时绑定站点、账号、设备。发送前再次校验当前身份，不跨账号/设备补传。未登录报告只保留本机，登录后必须在待传记录中预览确认，不自动转绑。账号变化清空自动内存日志上下文。
- 后台线程进行 HTTP，捕获入口只写有界内存队列；最终 Python 未处理异常最多进行一次有界本地持久化，不在崩溃钩子里联网。401/403等待身份恢复，429遵守 Retry-After，网络/5xx指数退避，普通退避上限6小时；400/409/413停止该条自动重试。服务端错误正文不进入日志。
- Python 主线程、后台线程、Tk 回调及严重运行错误有捕获入口。原生崩溃、强制结束、断电等通过未完成会话标记在下次启动生成“异常退出、原因待确认”报告，不上传 dump，也不声称能区分全部原生退出原因。正常退出删除自己的会话标记；并行运行实例通过文件锁区分。
- 服务器保留 30 天，仅新诊断模块授权管理员可查；后台权限、清理、数据库和部署由网站侧负责。诊断日志和原训练数据采集是独立流程。
