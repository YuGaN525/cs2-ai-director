## 3. 保留旧查询接口（WUPD-01）

`GET /api/director/client-releases?channel=stable`，匿名；省略 channel 仍默认 stable，只允许 stable/beta。使用原 `ApiResponse`：`success=true`、`code="OK"`、`data` 为数组。正常情况下每通道最多一个启用记录，零项表示“暂无发行”，不是“已经最新”。重复启用记录须服务端拒绝发布；若数据已冲突，返回明确故障，客户端不能取第一项。

每项保留：`id`、`version`、`artifactHash`、`artifactBytes`、`notes`、`enabled`、`revision`、`downloadPath`、`channel`。版本为三段非负十进制数，每段最多四位；当前方案不支持 `v` 前缀、`-beta`、`+build`，beta 使用独立通道。`artifactBytes` 为正整数，hash 为 64 位十六进制，notes 为纯文本，最多 2000 个 Unicode 字符。下载路径只能为 `/api/director/client-releases/{id}/file`。

同通道同版本的文件身份不可原地改变；修复包升版本并登记新 id。`revision` 只是原记录并发修订号，不是安全更新序号。高于通道当前版本时不降级；stable/beta 不跨通道选择。

接口建议 `Cache-Control: no-store`，禁止缓存撤回前的列表。保留错误封套：非法参数 400、冲突 409、限流 429、服务/对象不可用 503；429/503 支持 `Retry-After` 秒数或 HTTP 日期。不返回登录页面，不把错误伪装为 200 空列表。检查请求不要求账号、设备标识或 Cookie。

## 4. 独立信任配置与签名规则（WUPD-02）

程序当前验证原型为 `client_update_manifest.py`。以下字段和字节规则必须双端逐项验证后冻结。若网页侧需要更改，先回传差异，不能仅改服务端上线。

交付公开文件名 `client-update-trust.json`，内容仅以下三项：

```json
{
  "schema": "director-client-update-v1",
  "origin": "https://www.yuzibei.cn",
  "keys": { "<正式应用更新key_id>": "<32字节Ed25519公钥的标准Base64>" }
}
```

尖括号是说明占位符，不能作为实际配置交付。`origin` 为固定 HTTPS 源，无路径、查询、用户名密码；key_id 使用 1～64 个英文字母、数字、下划线或连字符；允许同时固定 1～8 个应用更新公钥。文件不超过 16 KiB。应用更新密钥必须与 identity/model 密钥不同；不得把私钥、账号密码、服务器令牌放入 exe、仓库或交接包。不要通过未受信接口动态获取并立即信任新公钥。

签名算法 Ed25519，签名为 64 字节标准 Base64。签名输入**仅为 payload 的规范 ASCII JSON 字节**，当前 v1 原型无额外前缀。固定 `schema`、`product`、独立密钥提供用途区分；不要套用现有模型用途前缀。字段名按 Ordinal 升序，无空格/换行，字符串规则等价于 Python `json.dumps(payload, sort_keys=True, separators=(',', ':'), ensure_ascii=True, allow_nan=False)`：非 ASCII 用小写十六进制 `\u` 转义；非 BMP 使用代理对；`/` 和 `<>&` 不额外转义；控制字符遵循 JSON；不规范化 Unicode；数值仅十进制整数，不允许 bool、浮点、指数或 NaN。

请使用独立测试密钥在隔离测试中生成向量，并交付 payload、规范字节文件、SHA256、signature、公钥和应通过/拒绝的预期结果。至少包含中文、换行、引号、反斜杠、`<>&/`、emoji；普通 C# JSON 默认转义可能与上述规则不同，必须逐字节比对。生产私钥不参与公开测试样本。轮换先交付含新旧公钥的客户端并确认覆盖，再切签名 key；旧客户端未知 key 必须拒绝，继续使用原程序及官网下载入口。

## 5. 新清单 API 与状态（WUPD-03）

程序侧已提供 `contracts/director-client-update-v1/`：14 个固定正反例、测试公钥、精确规范字节、schema 和文件 SHA256。网页侧可直接读取同机程序目录，先运行跨语言核验，再按网站新增 OpenAPI 与真实 HTTP 测试；这些是 example.org 测试数据，不是正式发行或公钥配置。

**提议路由，尚未上线：**

`GET /api/director/client-updates/manifest?channel=stable&platform=windows-x86_64`

匿名，只允许 stable/beta 和首期 `windows-x86_64`。不通过参数传递下载 URL、本地路径、命令、账号、设备或任意平台。200 使用原 ApiResponse，其 `data` 必须严格为：

```json
{
  "key_id": "<正式应用更新key_id>",
  "payload": {
    "schema": "director-client-update-v1",
    "product": "yuzi-cs2-director",
    "origin": "https://www.yuzibei.cn",
    "channel": "stable",
    "release_id": "10000000-0000-0000-0000-000000000001",
    "version": "1.14.0",
    "platform": "windows-x86_64",
    "sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
    "bytes": 200000000,
    "sequence": 1,
    "issued_at": 1804636800,
    "expires_at": 1804723200,
    "minimum_updater": 1,
    "notes": "纯文本发行说明"
  },
  "signature": "<64字节签名的标准Base64>"
}
```

示例 id、hash、大小、时间均为结构示意，**不能下载或发布该示例**。封套和 payload 均严格禁止未定义字段；日后扩展另定 schema/兼容版本。body 上限 256 KiB，规范 payload 不超过 32 KiB。

字段要求：

- `release_id`：小写规范 UUID，对应已启用且不可变的客户端文件；`version/sha256/bytes/channel` 与普通列表、下载实际内容完全一致，sha256 为小写。
- `sequence`：按 `(origin, channel, platform)` 单调递增的正 Int64；不能使用某个发行记录的 revision 代替。发布、撤回、重新启用、续签内容变化和 key 轮换均消耗新序号。数据库恢复也不能倒退；序号高水位应纳入恢复检查。
- `issued_at/expires_at`：UTC Unix 秒正整数，无浮点；客户端要求 `issued_at <= 当前时间 < expires_at`，有效期不超过 7 天。建议 24 小时、到期前续签；每次续签使用新 sequence。同序号必须保持**完整 payload 字节不变**，不能每次 GET 重新填时间。
- `minimum_updater`：更新协议版本，首期 1，不是客户端 semver。平台、版本、有效期、hash/bytes 任一不符即拒绝，不能降级到无签名安装。
- v1 不支持服务器指令强制安装或自动降版本。撤下坏包后发布更高 semver 的修复版；安装失败的本地原 exe 回退由程序实现，不能通过旧清单绕过防回放。

服务端持久化清单及签名，按通道/平台原子切换；签名失败时不能部分启用下载/列表。检查当前可用对象后返回 `Cache-Control: no-store`；文件与清单走同一 HTTPS 源，不重定向外部 CDN。客户端可拒绝所有重定向，因此必须直接返回资源。

无当前发行或被撤回：404 + 稳定业务码 `CLIENT_UPDATE_UNAVAILABLE`；参数非法 400；多启用/状态冲突 409；限流 429；签名未配置/功能关闭/对象损坏或缺失 503。禁止错误时回退到旧签名。所有错误都是“不能安装”，不影响账号或现有导播资格。

**撤回边界：**v1 清单只签当前可用包，不含撤回集合。客户端安装前必须再次联网读取 fresh 清单并验签，确认同一 release_id/version/hash/bytes/channel/platform 仍为当前目标；断网、404、过期或换包均阻止安装。续签 sequence 可变，但包身份必须相同。已在途下载可中止或收完后丢弃，不能进入可安装状态。若需要离线安装或签名撤回墓碑，须另扩契约，不能宣称当前方案已实现立即离线撤回。

## 6. 下载与续传（WUPD-04）

复用 `GET /api/director/client-releases/{id}/file`，依旧匿名。服务端从私有对象存储流式输出，不能通过可绕过撤回判断的静态路径暴露。每次 GET/Range 都重新确认已启用且文件身份正确。

| 请求 | 要求 |
| --- | --- |
| 无 Range | 200，完整 Content-Length，强 ETag `"<lowercase sha256>"`，`Accept-Ranges: bytes` |
| `Range: bytes=N-` + 匹配 `If-Range` | 206，`Content-Range: bytes N-(size-1)/size`，长度 size-N，ETag 相同 |
| If-Range 不匹配 | 200 完整文件；客户端必须重建 partial，不能追加 |
| 越界 Range | 416，`Content-Range: bytes */size`；不能当下载完成 |
| 发布状态撤回/文件不再允许 | 404（或明确不可用业务状态），不得继续新请求续传 |
| 对象缺失/坏 hash/存储错误 | 503，不返回成功空文件或错误 HTML |

输出 octet-stream、固定安全下载名、`X-Content-Type-Options: nosniff`；不压缩 exe，不使用弱 ETag，不把临时链接作为 downloadPath。实际大小/hash 是最终依据；不得只信上传表单元数据。新清单的元数据大小限制与文件流大小限制分开。现有客户端上传约 258 MiB 的限制应明确记录，如未来需要放宽先同步程序磁盘/大小上限，不能让任意超大声明消耗磁盘。

## 7. 后台、网页与数据迁移（WUPD-05～06）

沿用现有客户端登记、审核/发布权限，新增签名配置与发布能力时实时检查模块可见/可修改权限。普通 ADMIN 不自动获权。原接口保留 expectedRevision 语义；新发布事务补充 requestId 幂等和 expectedSequence，重放同请求返回原结果，内容不同 409；上传不能自动等于启用。

建议独立保存：应用签名元数据、通道平台高水位、发布/撤回审计、幂等命令；按项目现有迁移编号递增，不能改写已上线迁移。每通道/平台唯一启用约束由数据库与事务共同保证。状态变更同步维护旧列表、文件可见性与新清单；旧后台入口不能绕过新状态机。并发两名管理员启用不同包只允许一个成功。

后台展示版本/通道/平台、大小/hash、原 revision、新 sequence、签名 key_id、有效期、已登记/已启用/已撤下/签名未就绪、审计原因与发布时间。私钥不回显；发布错误说明具体状态但不泄露私有路径或密钥。

官网继续“介绍、使用说明、下载”结构。下载区展示 stable/beta 和实际版本、发布时间、大小、SHA256、纯文本发行说明；无包/撤回/服务故障状态准确。链接沿用 `/tools/ai-director`；不要改成依赖登录才能查看版本，也不要把可下载等同于账号拥有导播资格。

## 8. 验收矩阵（WUPD-07）

1. 旧客户端 1.11.0、当前候选访问旧 product/list/file 不回归；缺省 stable、beta 空/有包、重复启用、参数错误分别验证。

3. 错源/通道/平台、到期边界、未来时间、TTL>7天、最低更新协议不支持、序号倒退、同序号换 payload、序号并发与备份恢复不倒退。
4. 同目标续签、下载期间撤回/更换、安装前重新检查、服务关闭、对象损坏、429/503、跨源/同源重定向拒绝；禁止凭过期缓存进入安装。
5. 实际 HTTP 200/206/416/If-Range、断线重连、截断/多余字节、ETag 改变；程序以最终 bytes/hash/签名验收。
6. 权限/幂等/CAS/数据库迁移重复执行、启用失败不留半发布、后台旧入口不能绕过签名；网站业务原回归通过。
