## 任务4：受管记录与后台补传

- 统一客户端的导播/训练工作台/训练CLI共用 upload_protocol、UploadOutbox、UploadWorker 和 TrainingDataRuntime。SQLite WAL + synchronous=FULL、完整事务保存成熟记录、源读取进度、不可变gzip批次、重试状态和确认回执。账号/站点/设备维度隔离；绑定在采集时冻结，后续登录不能把未绑定或其它账号记录改归当前账号。
- 导播GUI的成熟标签通过有界非阻塞队列交给后台线程写盘，网络完全在上传线程。界面分别显示“写入中”和“已保存”；进程突然终止可能丢失尚在RAM缓冲的记录，但已提交SQLite的记录与已生成批次可恢复。缓冲溢出/非法样本明确累计未接收数量；写盘或容量失败保留当前待写项并重试，关闭时无法完成落盘会提示并保留窗口。不能宣称所有刚观察到的样本已持久化。
- SQLite为恢复源，旧decisions.csv保留为后台生成的兼容副本；崩溃可能使兼容副本少最后一条，受管记录可独立导出，不依赖扫描旧CSV恢复。新的训练操作只导入用户本次明确选择的CSV或工具生成的Demo CSV；普通CSV按500行分块事务登记，文件内容hash+行号身份支持同一不可变文件重放。正在增长或内容已修改的旧CSV会被视为新来源，跨快照样本去重待正式范围协议实现。
- 500行以内批次、单批1MiB gzip上限；默认逻辑数据配额256MiB（SQLite/WAL/索引等物理开销另计）。达到配额时保留原记录并显示失败，不自动删除原始或已确认数据。配额计数用事务触发器维护，避免逐条全表扫描。留存与自动清理策略仍待后续产品配置。
- 自动worker在启动/轮询时检测当前已认证身份的待传记录；仅调用capabilities支持的兼容完整批次端点。上传前再次核对账号/设备/站点与当前凭据；HTTP重定向拒绝，防止凭据随跳转离站。凭据仅从身份适配器内存回调取得，不写入队列/普通配置。
- 断网/503/429/5xx指数退避，身份401/403等待凭据变化，400/409/413/415/422保留为拒绝状态；协议/回执不匹配阻断。确认前核对uploadHash、行数、正例数、来源、质量、UUID、UTC时间等；只在SQLite确认事务完成后标已上传，不删除数据。租约ID防止过期worker确认新尝试。

- 导播“专业导播→决策模型→训练数据状态”和训练工作台同名按钮展示状态。--data-queue 可输出诊断并导出本设备未绑定记录；账号绑定记录通过同一outbox API按Binding导出，不能串账号。实际原生窗口1062×972/942×952及空态弹窗已检查，未覆盖所有DPI/主题/长时故障视觉排列。

## 任务5 / SRV-01：冻结兼容边界

协议：director-data-compat-v1；实现schema为decision-v1。权威文件：网站 contracts/director-data-v1，主仓库同目录为相同hash的同步副本；训练器直接复用主仓库SDK。包含OpenAPI 3.1、receipt/candidate-preview JSON Schema、capabilities fixture、合法/非法CSV及规范化黄金内容/摘要、fixture清单hash。

已实现/本地验收：

| 接口 | 鉴权 | 行为 |
|---|---|---|
| GET /api/director/capabilities | 公共，只返回非秘密能力 | enabled状态、schema、容量、错误/去重能力边界 |
| POST /api/director/data/batches | 当前网站登录JWT | automatic入口；file和source；回执含uploadHash |
| GET /api/director/data/batches | 当前网站登录JWT | 本人20条分页 |
| POST /api/admin/director-data/imports | 原模块可见+可修改权限 | manual入口，同一接收服务 |
| GET /api/admin/director-data/batches | 同上 | 后台批次列表 |
| GET /api/admin/director-data/batches/{id}/file | 同上 | no-store私有下载 |
| POST /api/admin/director-data/storage/reconcile | 同上 | JSON dryRun默认true；显式操作恢复检查/清理 |

uploadHash=本次上传文件原始字节SHA-256（gzip时为压缩字节），仅本次上传回执提供；contentHash=服务端按owner处理group等字段后的规范化CSV SHA-256。两者不能互换。确认回执createdAt统一UTC带Z，包括DB读回后的重复回执。收到回执仅表示兼容数据已接收，不表示ready。

兼容格式为UTF-8 CSV或单个完整gzip成员，8MiB上传/32MiB展开/50000行；只保留白名单，姓名/SteamID/任意文字与文件路径不进入服务端数据。超限413、坏CSV/非有限特征/损坏gzip422、无效请求400、401/403身份权限、配额429、关闭或对象不可用503。仍保留既有API外壳。自动/手动入口共用“owner+source+规范化完整内容”去重。

sampleExactlyOnce/requestIdentity/parts均明确false。future candidate-v2-preview只做共享fixture/设计校验，未知版本、缺身份、错特征顺序/数量拒绝；没有实现全候选上传、稳定来源范围冲突、/uploads登记或parts路由。未来协议需要source/session/range/request身份，仍由UP-A2/AID-12/14实现，不能以兼容整批重试声称样本级恰好一次。

## 任务5 / SRV-02：私有对象存储

ITrainingObjectStore/TrainingObjectKey和LocalTrainingObjectStore已补齐并注册：PutVerified/OpenRead/GetMetadata/Delete，以及孤儿发现和临时文件清理。key由服务端owner/source/canonical-hash构造，拒绝任意路径、无效hash、wwwroot及符号链接/reparse路径。Provider=local；其它provider缺实现明确失败，不伪装对象存储已提供。

写入先检查gzip与展开大小、完整性、规范化内容hash，再在同目录写临时文件并flush到磁盘，跨进程对象锁下原子发布。读取在同一打开句柄上校验gzip、内容hash及字节长度，返回实际存储SHA等元数据；损坏/缺失返回503，不伪造成功。相同内容重放不覆盖好对象；重新上传可修复缺失/损坏对象。Windows竞争重命名在测试中复现后已用对象锁解决。

DB事务失败不删除文件，防止误删其它重放正在引用的对象；留下可发现孤儿。恢复接口在与接收相同的PG跨实例事务锁下读取引用、检查缺失/损坏，默认dry-run；显式dryRun=false才清理超过24小时且无引用的对象及过期非活动临时文件。保留DB引用的数据，即使它缺失也只报告而不删除元数据。恢复工具使用短期扫描，首版不启用自动清理任务；大规模分页/长期维护调度另行实现。

配置：DirectorData:Enabled默认false；DirectorData:StorageRoot必须是私有持久卷；DirectorStorage:Provider默认local。MaxStorageBytes/MaxUserBytes/MaxDailyUserBytes沿用现有配置。多API实例必须共享相同私有卷（包括对象锁）；进程私有临时目录不能作为多实例生产存储。域名/TLS/代理请求体限制/资源/备份恢复的真实部署属于SRV-05。
