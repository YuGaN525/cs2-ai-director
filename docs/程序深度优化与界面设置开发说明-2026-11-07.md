目前具备可继续迭代的功能基础，适合渐进式整理。优先解决状态分散、配置应用时机不清、异步任务生命周期和信息展示密度，再优化决策执行路径。没有足够证据支持一次性更换 GUI 框架或重写整个导播引擎。

## 2. 功能保持规则

1. 保留同 exe 的导播、训练 GUI 和既有 CLI；不恢复旧独立训练器作为开发主仓库。
2. 原默认策略、8 个特征、现有切镜阈值/驻留/人工接管/死亡处理语义保持。更改策略需独立任务和效果证据。
3. 正式执行继续通过账号、设备、许可、正式模型校验；168 小时从服务端签发起算，不由 UI 操作、重启或上传续期。
4. 正式模型更新仍在停止导播后安全激活；本地训练只产候选。开发者模式不能绕过签名、撤销、到期和运行锁。
5. 默认本地先记录、联网自动补传；服务端持久确认前不标记成功；退出/切换账号不重新归属旧记录。
6. HLAE 组合键、双击保持时间与按键释放逻辑保留。自动输入要经过相同前台、人工接管和授权判断。
7. OBS、事件规则、叙事、道具运镜、出生点/包点、备份、旧 CSV 和 CLI-02 新采样均列入功能清单，界面整理不能遗漏。
8. 普通模式隐藏的是诊断细节和开发工具。已有有效高级配置仍保留，不因控件未创建就写回默认值。
9. 针对明确缺陷的修正单列测试和行为差异，例如“停止后不再执行过期动作”；不能混在纯代码搬迁里无记录更改。

## 3. 产品界面与操作流程

### 3.1 建议布局

主窗口采用“紧凑顶栏 + 左侧导航 + 中间可滚动内容 + 固定底部操作条”。窄窗口改为紧凑导航；不引入桌面浏览器壳。

```text
鱼籽杯 · AI 导播                 账号简要状态   设置   主题
┌──────────┬─────────────────────────────────────┐
│ 导播工作台 │ 游戏/数据连接   正式模型   授权状态       │
│ 训练工作台 │ 当前视角与运行状态、最近提示             │
│ 设置      │ 可上下滚动的当前页面内容                 │
│ 帮助      │                                     │
│ 开发工具* │                                     │
├──────────┴─────────────────────────────────────┤
│ 启动导播 / 停止导播       手动接管剩余时间   当前模式 │
└────────────────────────────────────────────────┘
*仅在开发者模式开启时显示
```

工作台只保留主要连接摘要、当前导播状态和主要操作。详细指标、原始候选、评分和多种模型调试信息从主页面移出。错误详情可展开滚动阅读。

“训练工作台”仍打开同 exe 的独立进程，避免训练占用导播 UI；可先保留独立窗口，统一导航名、主题和设置入口即可，不要求合并成同一 Tk 事件循环。

### 3.2 关键流程

| 场景 | 用户操作与可见结果 | 实现约束 |
| --- | --- | --- |
| 首次使用 | 账号初始化 → 选择/检测 CS2 → 安装 GSI 提示重启 → 配置所需运镜/可选 OBS → 启动 | 缺项卡片提供准确入口，避免连续弹出多次确认 |
| 启动 | 一次检查配置/授权/模型，启动监听后进入“等待游戏数据”，收到有效观战数据后开始决策 | 当前 GSI 服务在启动时才创建，不能要求“已有实时 GSI”才能点击启动，否则会形成死锁 |
| GSI 中断 | 显示数据中断及最后接收时间，保持受控等待，恢复后更新状态 | 区分“服务正在监听”和“收到有效数据” |
| 缺少可选组件 | 例如未连接 OBS，只提示对应功能未就绪 | 不把用户未启用的可选功能错误变成整个导播不可用；具体放宽规则单独验收 |
| 人工接管 | 显示剩余让位时间和原因；既有手动按键优先逻辑不变 | 当前“暂停开始/结束”用于事件规则，不能未经实现就把它标为“暂停全部 AI” |
| 调整设置 | 草稿修改 → 校验 → 应用；展示“已生效”或“下次启动生效” | 取消不会修改运行中的配置；失败不部分更新 |
| 停止/退出 | 先停止接受新执行请求并释放按键，再关闭服务、刷写记录、释放模型锁 | 长耗时收尾有进度；未落盘不能伪装保存成功 |
| 查看长说明/日志 | 鼠标滚轮、滚动条、PageUp/PageDown 可查看全部内容 | 新日志不能抢回用户已滚到上方的位置 |

### 4.2 状态与配置模型

建议增加不可变、可测试的状态快照，以下为内部设计而非新上传协议：

```text
AppStatus
  generation / updated_at / snapshot_age
  lifecycle: stopped | starting | running | stopping | error
  execution: ready | waiting_gsi | stale_gsi | manual_hold | blocked
  account: login_state / device_state / checked_at / lease_expires_at / reason_code
  model: active_id / active_hash / download_state / pending_id / validation_state
  game: listener_state / last_valid_at / spectating / phase / foreground
  recorder: persisted / buffered / not_accepted / last_error
  uploader: pending / inflight / confirmed / failed / last_error
  features: {feature_id: enabled, available, reason_code}
```

每个子状态带更新时间或明确未知值；读取快照不得触发网络、重新验签、扫描整个数据库或加载模型。UI 按快照渲染，低频变化数据缓存，数值倒计时在界面轻量计算。显示刷新频率与决策循环频率分离。

配置分三部分：

- `RuntimeConfig`：兼容现有程序配置键和值；逐项声明校验、默认值与生效时机。
- `UiPreferences`：例如 `schema_version=1`、`developer_mode=false`、`theme=dark`、字号、窗口状态、日志跟随；不传入决策算法。
- `Secrets`：沿用现有设备 DPAPI 保护；DeepSeek/OBS 明文配置是既有实现事实。若迁移保护存储，需另加迁移和备份兼容测试，不能在本轮搬迁时静默丢失旧值。

`save_config()` 当前只保存 DEFAULT_CONFIG 中的键，因此 UI 偏好不能只是临时塞入现有 cfg。偏好保存应原子写入、有版本迁移，导播/训练器两进程更新字段时应按版本合并或加锁，避免互相覆盖。

建议设置生效规则：

| 类型 | 规则 |
| --- | --- |
| 主题、导航、开发者模式 | 即时更新界面；不重建引擎 |
| 普通界面偏好 | 即时生效，持久化失败给提示 |
| CS2 路径、GSI 端口、输入后端、模型激活 | 停止后或下次启动生效；运行中显示待应用 |
| OBS 主机/端口/凭据 | 原子保存后显式重连，不修改一半连接参数 |
| 策略/规则参数 | 第一阶段统一要求停止后应用；后续只对已证明安全的键支持快照热更新 |
| 账号退出/撤销/许可到期 | 立即进入现有执行禁止机制；不能等待设置页面关闭 |

## 5. 视觉与滚动规范

### 5.1 网站来源与桌面映射

网站样式入口顺序为 `main.scss` 中 design → motion → appearance → refresh → filters。暗色基础表面由 refresh 覆盖；浅色使用 `html[data-theme="light"]` 的更高优先级定义。不能只读取 design.scss 就认定最终配色。

| 桌面令牌 | 黑金主题 | 浅色主题 | 源码依据 |
| --- | --- | --- | --- |
| 页面底色 | `#090909` | `#f5f3ed` | refresh / appearance |
| 卡片底色 | `#151512` | `#ffffff` | 同上 |
| 次级表面 | `#1b1b17` | `#faf8f2` | 同上 |
| 主文字 | `#f2f0e9` | `#242319` | design / appearance |
| 次文字 | `#b7bdc8` | `#55564e` | 同上 |
| 交互强调 | `#d4af37` | `#85620e` | 同上 |
| 强调按钮文字 | `#171207` | `#ffffff` | 同上 |
| 成功 | `#62d4a2` | `#11784d` | 同上 |
| 错误 | `#ff7272` | `#bc3038` | 同上 |
| 警告 | `#e9b95f` | `#885911` | 同上 |

桌面统一中文使用 Microsoft YaHei UI，建议正文 10～11pt、分组标题 12～14pt、页标题 18～20pt；字体尺寸与 DPI 一并验收，不混用 CSS px 和 Tk pt。间距以 4/8/12/16/24 为基准，标题/说明/字段/操作分层。成功、警告、错误同时带文字和图形，不只靠颜色表达。

优先保留 Tk/ttk。先实现主题令牌、输入/按钮/状态卡片/导航一致性；少量圆角容器按能力实现，保留原生控件焦点与键盘行为。不要为追求网页动画和渐变，重写全部控件或新增重型依赖。若实测证明现框架在高 DPI、可访问性或维护成本上无法达标，再形成单独框架迁移验证任务，不能与引擎重构同时进行。

### 5.2 滚动必须满足的规则

1. 设置、帮助、错误详情、长结果说明、开发者页、训练器参数和弹窗统一使用公共纵向滚动容器。外部顶栏/主要操作条固定，内容不通过挤小字体塞入窗口。
2. 鼠标指向 Text、Treeview、Listbox 等可滚动控件时优先滚该控件；到达边界再按明确规则交给父页面。普通内容区域滚动当前页面。
3. 不使用进入页面后 `bind_all`、离开后 `unbind_all` 的全局争抢方式。通过窗口级路由或 bindtags 管理，解绑只清理自己注册的回调；切页、弹窗、销毁后不得残留。
4. 处理高精度滚轮/触控板的小 delta 累积，不能直接 int(delta/120) 将小幅滚动全部截断。保留滚动条拖动和键盘 PageUp/PageDown/Home/End。
5. 宽度变化时更新文本自动换行；正常说明无需横向滚动。hash、长路径可复制，完整值放可滚动详情，不用不可恢复的截断。
6. 日志只有在用户已经位于底部且“跟随最新”开启时自动滚到底；用户向上滚后维持位置，显示未读数量或“回到最新”。日志显示上限不等于删除本地持久记录。
7. 无溢出时隐藏或禁用无用滚动条；切换主题/开发者模式保留页面焦点和合理的滚动位置。
8. 窗口初始尺寸按当前显示器工作区限制。验收至少覆盖 1366×768、1920×1080，在 100%/125%/150%/200% DPI 下的有效工作区；不强制最小高度超过屏幕。高 DPI 小有效宽度切为单列/紧凑导航。

## 6. 底层重构方案

建议目标结构如下；路径为拟新增，不表示当前已经存在：

```text
cs2_ai_director.py          # 兼容入口与装配，逐步变薄
trainer_gui.py              # 训练入口兼容层
director_core/             # 无 GUI/网络/按键的状态、特征、策略、回放
director_app/
  config_service.py        # 迁移、校验、草稿、应用、版本
  status_service.py        # 聚合快照、原因码、能力状态
  controller.py            # 启停/操作编排
  lifecycle.py             # 服务与任务收尾
  execution.py             # 请求/回执/取消/有效期
  diagnostics.py           # 脱敏诊断、性能统计
director_adapters/
  gsi.py                   # GSI 接收与边界校验
  windows_input.py         # 窗口、按键、手动接管
  obs.py                   # OBS 连接与动作
  recording.py             # 持久记录和兼容文件适配
director_ui/
  theme.py / components.py / scroll.py
  workspace.py / settings.py / developer.py / trainer.py
```

账号、模型、上传等既有稳定模块先保留原路径，通过服务接口组合。避免同时重写已验收的鉴权和持久协议。旧模块保留必要 re-export，最后再缩减，确保测试、CLI 和 PyInstaller 分析仍能找到依赖。

依赖方向：UI → 应用服务 → 纯核心/端口；外部适配器实现端口，由入口装配。纯核心不反向导入 Tk、Windows 按键、HTTP、SQLite 或账号 UI。

执行请求建议包含 session/generation、快照序号、创建时间、有效期、动作类型/目标、配置版本；回执区分 accepted、started、sent、observed、failed、cancelled。键已发送或 OBS 请求成功不等于节目镜头已确认。确认依赖 GSI/OBS 反馈，真实播出时间仍需 CLI-04 的记录链路。

异步执行必须保序，不能无界排队或稍后补发过期切镜。普通 POV 可按规则替换未开始的过期请求；HLAE 组合键作为不可拆散的序列，取消时仍完整释放已按下的键。执行前重新检查授权、会话代次、前台和人工接管；停止后旧请求不得跨到下次启动。

热路径优化顺序为：先测量，再消除重复计算和同步I/O，最后考虑改变数据结构。现有候选缓存应保留；如果引入配置热更新，缓存键必须纳入配置/模型代次，并测试近期伤害窗口到期等时间相关失效。显示用完整状态、日志格式化和统计聚合按需/降频计算。模型文件解析可在后台完成后原子替换引用，正式模型激活仍遵守既有停止锁。每项缓存或线程调整均需与旧输出对比，不能以新缓存掩盖旧状态。
